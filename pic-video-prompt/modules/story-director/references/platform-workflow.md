# 平台工作流

本文件负责 Story Director 的人物资产衔接、分镜统一确认、视频生成段划分、提示词编写与视频节点配置。首次项目确认的信息识别规则、缺失项弹窗及全部选项直接写在 `SKILL.md` 中，不依赖本参考文件触发。

## 1. 首次确认后的流程衔接

用户初始消息已经明确的项目直接锁定，只对缺失项目调用交互式弹窗。七项信息全部明确后才能进入资产阶段，不要求用户重复确认已经提供的剧情、总时长、剪辑镜头数量、画幅、资产范围、画面风格与声音要求。总时长和剪辑镜头数量是两个独立必填项；只提供其中一项时，必须通过弹窗补问另一项。

先完成人物面容与穿搭弹窗和16:9人物三视图生成。选择“人物和场景”时继续生成核心场景资产，选择“人物和道具”时继续生成核心道具资产；所选节点全部建立并绑定后再进入剧情判断、视觉规范与横向分镜。当前项目的修改、确认、提示词转写和生成问题修复都继承现有信息，不重新启动前期提问。

## 2. 分镜统一确认

完整视觉规范与横向分镜表输出后，只提供一次统一确认，不逐镜询问。优先使用当前平台支持的交互式选择组件，固定提供：

```text
1. 确认故事与分镜，继续制作
2. 修改剧情或指定镜头
3. 重新生成故事与分镜
4. 跳过生成段说明，直接输出视频提示词
```

确认组件必须是本轮最后一个动作。调用或显示后立即停止，不继续划分生成段，不编写完整视频提示词。

交互式组件不可用时使用以下文字：

```text
请统一确认以上故事与分镜。确认后回复“确认故事与分镜”；需要修改时直接写明剧情改动，或回复“修改镜头05：具体要求”；需要重做时回复“重新生成故事与分镜”；需要直接转写时回复“直接输出视频提示词”。
```

用户修改剧情时，重新输出完整故事逻辑、受影响的视觉规范与完整分镜表；用户只修改指定镜头时，只输出受影响的分镜行，并同步修正后续时间码和连续性。修改完成后再次进行统一确认。

## 3. 视频生成段划分

用户确认分镜后，先区分两个层级：

- 剪辑镜头：横向分镜表中的一行，服务最终成片节奏；
- 视频生成段：一次提交给视频生成模型的完整片段，可以包含一个剪辑镜头，也可以包含多个连续剪辑镜头。

用户没有指定视频生成模型时，生成段判断与节点配置统一使用2.5模型；用户明确指定其他模型时才更换。

### 3.1 单节点优先｜最高优先级

剪辑镜头只是一个视频内部的切镜，不能直接当作视频生成段。总时长处于所选模型单次生成上限内，并且模型支持提示词内部切镜时，默认把全部剪辑镜头合并为一个视频生成段，只建立一个视频节点。景别变化、机位变化、运镜变化、同一旅拍地点内的取景变化以及分镜表存在多行，都不是拆分视频节点的理由。

固定示例：10秒成片包含5个剪辑镜头时，建立一个10秒视频生成段，在同一份【镜头与动作时间线】中依次写入镜头01至镜头05，然后只创建一个10秒视频节点。禁止建立5个节点，禁止把5个镜头分别生成。

只有以下三种情况允许建立多个视频生成段：

1. 成片总时长超过所选模型的单次生成上限；
2. 用户明确要求分段生成或为指定镜头单独建立节点；
3. 当前所选模型明确不支持提示词内部切镜。

拆分前必须先检查以上条件。没有命中任意条件时，生成段数量固定为1。

需要拆分的长视频中，满足以下条件时，多个剪辑镜头仍应尽量合并进同一个视频生成段：

- 使用同一场景与连续时间；
- 人物年龄版本、面容、发型和服装保持一致；
- 核心道具的持有人、位置与状态能够连续继承；
- 内部切镜数量和动作负担处于所选模型能够稳定完成的范围；
- 合计时长不超过该模型的单次生成上限。

长视频已经超过单次生成上限时，可以结合以下变化选择拆分边界：

- 场景切换；
- 现实与回忆切换；
- 人物年龄版本变化；
- 换装或核心造型变化；
- 核心道具发生难以在一次生成中稳定完成的重大状态变化；
- 群体调度、复杂特效或动作负担超过单次稳定执行范围；
- 当前段继续延长会超过模型单次生成上限。

只有满足允许拆分条件并确实需要多个生成段时，才输出：

| 生成段 | 对应剪辑镜头 | 建议生成时长 | 场景与资产 | 拆分原因 |
|---|---|---:|---|---|

划分生成段不改变已确认的剪辑镜号、镜头顺序、对白、动作结果和最终成片时间。每个生成段内部时间从0秒重新开始，时间线标题保留源镜号。

## 4. 视频节点创建与提示词写入

用户确认分镜后，先在视频节点之外为每个生成段建立唯一的 `final_video_prompt`。完整写作、质量检查和结构检查全部通过后才能创建节点。`final_video_prompt` 严格使用 Story Director 的五个主板块：

```text
【故事前提与资产绑定】
【画面质感与光影】
【镜头与动作时间线】
【对白、环境声与BGM】
【负面提示词】
```

提示词规则：

- 一份提示词对应一个视频生成段和一次独立投喂；
- 同一生成段内的全部剪辑镜头写入同一份时间线；
- 每份提示词独立完整，不使用“同上一段”代替人物、场景、道具、质感、声音和高风险约束；
- 资产只绑定当前生成段真实使用的图片编号；
- 提示词使用中文，保持可直接投喂，不在正文中插入教学解释；
- 用户只索取指定生成段时，只输出该段完整提示词；
- 用户上传失败结果时，先诊断原因，再输出最小范围的替换时间段或替换生成段。

结构断言：

```text
第一个标题必须是【故事前提与资产绑定】
第二个标题必须是【画面质感与光影】
第三个标题必须是【镜头与动作时间线】
第四个标题必须是【对白、环境声与BGM】
第五个标题必须是【负面提示词】
五个标题各出现一次
```

出现【素材职责】【人物】【视觉风格】【声音】【镜头】【正文】中的任意一个顶级标题，均判定为结构失败。禁止创建节点，必须先改回五个固定板块。原生资产引用只允许出现在【故事前提与资产绑定】的对应资产行，不得触发平台模板重新排版。

完整提示词编写完成后，必须立即调用当前平台可用的视频节点创建或配置能力，不等待用户再次要求“建立节点”。执行顺序固定为：

```text
确认生成段数量
→ 在节点外完成并校验 final_video_prompt
→ 对生成段循环创建视频节点，禁止对剪辑镜头逐行循环
→ 按顺序命名节点
→ 设置已确认模型、画幅与该段生成时长；未指定模型时选择2.5
→ 连接本段实际使用的人物、场景和道具资产
→ 支持@提及时，通过资产选择器把对应资产作为原生引用实体插入第一板块
→ 将带有原生资产引用的 final_video_prompt 写入节点提示词输入框
→ 保存为可生成状态
→ 检查节点内容并报告结果
```

优先创建空白视频节点，再逐项设置模型、时长、画幅、资产与提示词字段。禁止使用“根据分镜自动创建视频”“根据脚本自动填写节点”一类会重新编写提示词的入口。平台只能负责保存和绑定，不参与改写内容。

节点配置要求：

- 一个视频生成段对应一个视频节点，节点数量不得少于或多于生成段数量；
- 节点循环的输入对象必须是“视频生成段”，不能是横向分镜表的单行镜头；
- 生成段数量为1时，只允许调用一次视频节点创建能力；
- 10秒5镜头项目的节点数量固定为1，节点时长固定为10秒，五个镜头全部写入同一个节点提示词的时间线；
- 节点按“视频段01｜核心事件”“视频段02｜核心事件”顺序命名；
- 用户没有指定模型时，节点模型固定选择2.5；不得停留在平台自动选择、上次使用或空白模型状态；
- 节点时长使用该生成段的建议生成时长，节点画幅使用项目已经确认的画幅；
- 只连接该段实际使用的资产；人物三视图作为身份、面部、发型、身材与服装参考，不把纯白背景和设定板排版带入视频画面；
- 当前平台支持 `@` 资产提及时，必须点击或调用资产选择器，依次选择本段实际使用的人物、场景和道具；不得只键入普通文字“@名称”，不得只连接参考字段而省略提示词中的原生引用；
- 每项原生资产引用只在【故事前提与资产绑定】的对应资产行出现一次；人物时间线继续使用角色名，不重复插入 `@人物`；
- 整份带有原生资产实体的 `final_video_prompt` 写入节点对话框或提示词输入框，不压缩、不翻译、不改写、不拆散到聊天说明中；
- 禁止让节点代理根据人物、声音、镜头字段重新生成提示词，禁止套用节点默认模板，禁止生成【素材职责】【镜头】【正文】式结构；
- 写入后重新读取节点字段，并检查每个资产引用的实体类型与目标资产ID；界面只显示普通“@名称”文字、引用无法点击或目标ID不符，均判定为绑定失败；除平台原生引用编码、首尾空白与换行编码差异外，提示词必须与 `final_video_prompt` 一致；
- 回读内容出现标题替换、板块增减、镜头摘要、正文重复或时间码丢失时，立即覆盖为 `final_video_prompt` 并再次回读，最多修正两次；仍不一致时停止，不启动生成，并明确报告节点写入失败；
- 回读时逐行识别完全匹配的顶级标题。结果必须严格等于五个固定标题；【镜头01｜时间｜内容】属于第三板块的子标题，不计入顶级标题。检测到独立一行的【正文】时必须删除该标题，并把其详细镜头内容并入【镜头与动作时间线】；
- 确认节点名称、模型、时长、画幅、资产与提示词均已保存；平台支持 `@` 时，节点内实际使用的每个人物、场景和道具都必须存在一个有效原生引用实体；
- 节点只保存到可生成状态。未经用户明确要求，不点击生成、不启动渲染、不提交视频任务；
- 如果平台把“创建节点”和“开始生成”绑定为同一个不可分离动作，在调用前暂停并向用户说明会直接开始生成，获得明确许可后再执行；
- 如果当前平台没有视频节点创建或配置能力，不能假称节点已经建立。此时在对话中交付每段完整提示词，并明确说明节点未能自动创建；
- 部分节点创建失败时保留已经成功的节点，只重试失败部分，并逐项报告成功与失败状态。

创建前进行数量断言：

```text
expected_node_count = 视频生成段数量
如果总时长未超过模型单次上限且用户未要求拆分，则 expected_node_count = 1
实际创建次数必须等于 expected_node_count
```

全部节点配置成功后，只用简短结果说明已经建立的节点数量、名称、所用模型与节点状态。除非用户要求，不在聊天中重复粘贴已经写入节点的长提示词。

## 5. 流程优先级

```text
项目前期确认
→ 人物面容与穿搭选择
→ 16:9人物三视图生成
→ 按资产范围生成场景或道具节点
→ 剧情与情绪锁定
→ 视觉规范与标准横向分镜
→ 统一确认并暂停
→ 视频生成段划分
→ 每段完整提示词
→ 自动创建视频节点并写入提示词
→ 等待用户启动生成
→ 生成结果诊断与局部修复
```

用户明确说“直接输出”“跳过分镜”或“直接写视频提示词”时，跳过视觉规范、分镜与确认阶段，但仍补齐会实质改变结果的必要信息。用户已经提供确认版分镜时，从视频生成段划分开始。当前任务只是局部修复时，直接进入诊断与局部重写。
