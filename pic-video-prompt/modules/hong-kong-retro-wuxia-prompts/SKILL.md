# 港风复古武侠 · 江湖风云

把新题材写成具有这套人物、光色和实物质感的独立电影瞬间。默认重视人物，避免把组图写成依赖同一张脸的连续剧情。

## 输入与输出

- 一句想法：直接给一个画面构思、一条可复制的 MJ 英文提示词、一条独立编写的 ImageGen 中文提示词，以及该画面的中英文负面约束。
- 指定数量：严格给足数量，每张保留自己的构思和完整提示词。只说“一组”时，说明默认四张后执行。
- “先给思路／先确认方向”：只给构思，等用户确认后再编译提示词。只要一种模型时，只输出该模型。
- 普通组图以人物近景和中景为主，改变人物年龄、性别、衣色、动作、地点；双人画面、单人大场景和空景按用户要求安排。单张不强行塞入多个动作。
- 默认作品为横向 **16:9**。用户指定其他比例就重新安排构图。提示词卡片的 3:4 页面比例不是作品比例。
- 参考图：先看真实画面范围，逐图记录景别、左右位置、动作、遮挡、光色和材质；用户明确要保留的内容优先于默认风格。局部修复只改导致问题的关系。
- 用户没有要求生成时，不调用图片生成工具。已要求生成时再使用当前可用的生成工作流。

## 每次执行的最短路径

1. 先读 [风格 DNA](references/visual-dna.md) 和 [原生编译规则](references/prompt-compiler.md)。按题材读 [镜头配方](references/shot-recipes.md) 的相关段落。
2. 写一行内部构图合同：比例；人数；景别与人物大小；位置和朝向；一个动作；道具及接触点；光源与色区；允许变化的部分。
3. **先写画面，后写风格**：景别与位置 → 人物可见特征 → 一个动作及道具关系 → 环境三层 → 光色与材质 → 简短摄影收束。
4. 分别编译 MJ 英文和 ImageGen 中文；两者保持同一人数、动作、道具数量、位置、比例。中文不是英语逐句硬译，也不掺 MJ 参数。
5. 对照下方自检后交付。不要输出内部打分、虚构的生成结果或“保证复刻”承诺。

## 必须守住的风格骨架

- 人物近景让眼神、脸部体积和一个手势可读；远景让身体轮廓和环境关系可读，不同时要求“脸占满画面”。
- 暖肤色对应冷蓝灰、暗青或林间冷绿环境。红伞、锈红衣带等只作有需要的局部色块；不要求每张都有红色。
- 交领、浅色内领、布腰带、粗棉麻外袍、黑发碎发、普通剑鞘，形成可见的江湖人物；衣料有重量，钢铁反光克制。
- 轻微胶片颗粒、柔和高光、自然肤质、真实布景与摄影景深。运动时背景可以有方向性拖影，脸和动作重点保持可辨。
- 风是画面关系：头发、窄带、披风方向统一，重布滞后于轻发；没有无缘由的漂浮大袖、魔法光效或盔甲增生。
- 这是从用户的 AI 生成图提炼的视觉语法，不宣称真实胶片、某个演员、具体导演、固定镜头或历史年代的拍摄事实。

## 参数与来源边界

默认使用 **通用文字模式**，不自动添加个人配置、参考链接或高清参数。项目的 MJ 输出以 `--v 8.2` 结尾；基本参数为 `--ar 16:9 --v 8.2`，比例随用户输入变化，必要的 `--no` 放在版本参数之前。

只有用户明确说“沿用本期原配置”或提供自己的配置时，才进入配置继承模式。**若只要求“原 profile”，仅继承 profile，其他参数仍用通用模式。** 原样本共同使用 `--profile z4yrncu`，并使用 `--raw`、`--chaos 3` 和 `--hd`；这些是生成记录，**不是已证明可由文字替代的效果**。具体继承规则见编译文档。未要求修改版本时保留项目约定；用户明确指定新版本或能力不明的参数时先核实官方文档，不能默默忽略。

来源证据位于 [18 张记录](references/source-evidence.json)、[18 张对应总览](references/images/source-contact-sheet.jpg) 和 [策马原图](references/images/03-mounted-anchor.png)。总览按从左到右、从上到下排列。图片是视觉参考，不是可直接粘进 MJ 的网络地址。

`actual_mj_prompt` 与 `recorded_negative_en` 是来源记录；`native_imagegen_zh` 是此前编写的中文；`suggested_negative_*` 和本 Skill 的新例子是后续建议。绝不把建议负面词称为图片的原始参数。

## 交付前自检

- 景别与身体可见范围是否一致？坐姿、站姿、背影、全身有没有被默认的美女近景覆盖？
- 人数、道具归属与接触瞬间是否唯一清楚？两把剑各有一个持有者；徒手场景腰后和背后不冒出刀剑。
- 两种语言的构图和动作是否相同？负面词有没有禁止所需的人物、运动模糊、伞、花瓣或兵器？
- 所有新人物是否被写成同一位年轻女性？组图能否在没有人脸连续性的情况下成立？
- 新比例是否改了画面组织，而不只是改参数？空景是否清除了人物和“脸部暖光”等残留？
- 未指定的 profile、seed、sref、参考 URL 有没有被凭空加上？版本参数是否处于 MJ 末尾？

需要 JSON 批量交付时参考 [六类示例](references/examples.json)。运行 `python scripts/audit_prompt_set.py 路径/提示词.json` 检查数量、双语字段和参数冲突；脚本只验证文本合同，不能证明生成后的脸、手、兵器或风格准确。修复空间关系后仍需用户实际出图检验。
