> **入编**：2026-11-17，SSS 动作场面语料 5000 条全量原文入编。
> **原文**：`场面语料5000条.txt`，5000 条记录逐条保留，编号 SSS-0001—SSS-5000。
> **定位**：**场面设计层 / 情境创意库**。解决“这一场为什么打、在哪里打、道具怎样改变攻防、局势怎样升级”，不是直接可粘贴的提示词成品。
> **使用边界**：来源作品与场景字段只作检索线索和创意参照，不视为影视史实或动作细节的权威核验；不得把来源字段当成已验证考据。

## 一、记录结构与类型分布

每条记录采用固定结构：

```text
【编号｜来源｜类型｜情景｜场景/道具｜外观｜动作】
```

| 字段 | 在设计中的用途 |
|---|---|
| 来源 | 回溯本条语料的题材与场面标识；不是必须写入成稿的内容 |
| 类型 | 辅助映射写实 / 真人 / 2D 路线 |
| 情景 | 冲突目标、劣势、逼迫条件、胜负转折 |
| 场景/道具 | 空间锚、反馈介质、可借力/可破坏物、环境互动 |
| 外观 | 角色辨识与视觉签名参考；已有资产时不得覆盖资产 |
| 动作 | 攻防因果与场面链底稿；仍须按 R7/R16 重写为执行级动作 |

| 类型 | 条数 | 主要用途 |
|---|---:|---|
| 实拍 | 2797 | 真人路线②：近身缠斗、追逐、环境道具、枪战与战术情境 |
| 动画 | 803 | 2D 路线③：夸张动作、动漫场面、风格化攻防 |
| 游戏大招 | 500 | 大招结构、起势—释放—命中—收势；按目标画风归路线①或③ |
| 游戏 CG | 500 | 写实渲染路线①：高武、科幻、巨物、电影化场面 |
| 漫画 | 300 | 2D 路线③：构图、格子式节奏、符号化冲击 |
| 游戏实机 | 100 | 机制驱动打斗、资源限制、场景互动；按成片画风转译 |

**类型不是自动路线判定。** 最终路线只看用户要求和目标画风；语料类型只用于缩小检索范围。

## 二、在 ling 体系中的层间分工

| 层 | 文件 | 回答的问题 |
|---|---|---|
| 场面设计层 | **26** | 为什么打、在哪里打、局势与道具怎样变化 |
| 角色与招式设计层 | `04` | 谁用什么战斗偏好，哪些招符合角色 |
| 招式与特效词库层 | `17–22` | 招式骨架、轨迹、异象、材质、反馈怎样写 |
| 人体动作执行层 | `24` | 徒手动作怎样选型，受击与步伐怎样分级 |
| 时间与镜头组织层 | `03 / 12 / 16 / 25` | 在单条、多镜或多参考图输入下怎样组织成稿 |
| 质检层 | `13` | 哪些写法虽然精彩但不可交付 |

**调用顺序**：先读 `26` 找 2–4 个情境候选 → 提炼“目标 + 障碍 + 环境因果 + 局势变化” → 进入 `04 §八` 按角色路由招式词库 → 用 `24` 补人体执行与受击 → 按输入方式写 `03` 或 `25` → 过 `13`。

不要为了“使用语料库”而硬塞场面。用户已经给出明确剧情、参考图或场景时，以用户材料为准，`26` 只补缺口。

## 三、检索协议（实际取用时必须检索原文）

### 3.1 按路线与情景检索

在 `references/26-动作场面语料库/场面语料5000条.txt` 内做全文检索，优先组合“类型 + 场景/道具/情景”，不要只搜大词“打斗”。

| 需求 | 检索示例 |
|---|---|
| 真人仓库近战 | `类型：实拍` + `仓库` |
| 雨夜追逐 | `雨夜` 或 `暴雨` + `追逐` |
| 以少敌多 | `围困` / `围攻` / `重围` |
| 可破坏环境 | `玻璃` / `木桥` / `脚手架` / `冰面` |
| 夺械与反制 | `夺过` / `夺下` / `反折` / `格挡` |
| 仙侠巨物 | `类型：游戏CG` + `法相` / `巨龙` / `巨兽` |
| 大招设计 | `类型：游戏大招` + `火焰` / `雷` / `剑` |
| 2D 风格化场面 | `类型：动画` 或 `类型：漫画` + 具体题材词 |

一次取 2–4 条候选即可。先看它们的**关系结构**，不要按编号顺序拼前几条，也不要把多条动作串成超出时长预算的流水账。

### 3.2 五元组提炼法

从候选记录中只提炼以下五项，再按当次角色与场景重组：

```text
冲突目标：这一回合要得到/守住/逃离什么？
压迫条件：人数、地形、武器、时间或资源造成什么劣势？
关键道具：哪个物件真正改变一次攻防，而非只作摆设？
因果转点：哪个命中/破坏/夺械让局势反转？
升级方向：下一段是更快、更重、更险，还是更大？只选一个主方向。
```

### 3.3 从语料到成稿的改写要求

1. **换角色**：知名角色名和专有不必要名词不自动带入；按用户资产写外观与身份。
2. **换动作执行**：把概括性“连击 / 大战 / 击退”展开为形态、方向、结果；徒手与受击用 `24` 校准。
3. **换场面逻辑**：保留“因为 A 所以 B”的因果，不照搬与原场景不相容的动作。
4. **过时长预算**：一条只保留一个主情境、一个核心道具机制和一个主要反转。
5. **过反模板化**：若换角色后整段仍一字不动，说明只是照抄，回 `04 §8.2` 变奏。

## 四、红线与冲突优先级

语料是创意来源，**不能覆盖 ling 的执行红线**：

* 语料中抓栏杆、沿栏板滑行等动作，若命中 `13 R15` 的结构件禁令，改为地面、墙体或明确可承重结构借力。
* 语料中的“后仰闪避、残影、定格、子弹时间、收势摆拍”等，按 `02 §四`、`13 R19` 与 `25 §六` 的平台分流处理，不原样照抄。
* 语料中的血腥、处决、断肢或真人超人体极限动作，按所选路线删除或降级。
* 语料中的多武器切换与道具回手，必须经过 `13 R18` 和 `16 §4.3`；已经脱手/毁坏的物件不得无因果复原。
* 语料中的多地点、多阶段、多机制，压到当次时长预算内；30 秒多参考图稿继续受 `25 §三` 的密度上限约束。
* 语料中“来源”字段涉及的知名形象，只提取可泛化的动作与情境；除非用户明确要求并提供资产，不把角色名当作生成锚点。

## 五、最小使用示例

**需求**：真人、雨夜、仓库、主角被三人围堵，要利用环境反打。

1. 检索“类型：实拍 + 仓库 / 雨夜 / 围困”，挑 2–4 条。
2. 提炼：目标是突围；压迫是人数与出口被封；核心道具只选货箱或叉车之一；转点是撞翻货箱改变包围缺口；升级方向是更快，不再追加新武器。
3. 用 `24` 选短上步、近距勾拳、格挡反应和中击受击；每击补方向与落点。
4. 用 `11 §六` 写近景机枪节奏；用 `16` 的空间/状态/道具锁保证货箱翻倒后持续在场。
5. 交付前过 `13`，尤其 R1、R4、R15、R16、R18。

**合格结果不是某条语料的中文复述，而是一个只属于当前角色、当前场景和当前时长的新场面。**
